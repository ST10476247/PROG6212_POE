RaceDay — Entity Relationship Diagram (Part 1)

8 entities · 9 relationships · 1:1 extensions for Organiser / Participant · 1:1 Result per Enrolment

1. USERS → ORGANISERS / PARTICIPANTS

1:1 extension tables — Users.Role determines which table the row joins to.

2. ORGANISERS → EVENTS

1:N ownership — each event belongs to exactly one Organiser.

3. EVENTS → CATEGORIES

1:N (e.g. Comrades has Men Open, Women Open, Veterans Men, etc.)

4. PARTICIPANTS + CATEGORY → EVENT ENROLMENTS

N:M join table with UK(ParticipantId, CategoryId); unique per participant+category.

5. ENROLMENTS → RESULTS

1:0..1 — an enrolment produces at most one result (Finished / DNF / DNS / DQ).

6. EVENTS → WEATHER_SNAPSHOTS

1:N — supports "live weather" preparation feature for race day.

Cardinality cheat sheet: || = exactly 1,   o| = 0..1,   }o = 0..N,   ||--o{ = one-to-many (parent required, child optional/many).
